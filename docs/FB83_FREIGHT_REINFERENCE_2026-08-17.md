# FB83 真实头程反推重算（2026-08-17）

## 结论

本轮只使用现有 `calibration_records.jsonl` 的原始 v1.3 baseline、实际纯头程、货代和用户备注做确定性重算；没有重新调用 AI、没有覆盖任何历史 baseline、没有修改 2.6.1 主软件。

本轮最重要结论：

1. **83/83 都可以反推出“费率等价计费重量”**（billed-weight equivalent），因为每条都有明确实际纯头程与货代。
2. 其中 **79 条 evidence=B**，可作为后续数值边界证据；**4 条 evidence=D（002/025/041/075）** 仍保留，但因数量/重量/页面事实不完整，不进入产品级数值规则。
3. 当前结构化记录里 **83/83 的 actual.weight 和 actual.dimensions 都为空**。因此，**仅凭现有结构化数据，0 条能够证明“实重主导”或“体积重主导”**。
4. 因无法证明体积重主导，当前 **0 条可以把真实头程直接转换成“近似运输总体积”**；更不能反推出唯一长宽高。
5. 真实头程仍然很有价值：它给每条记录提供了一个**费率等价计费重量**。在确认货代没有额外最低计费/进位规则的前提下，它还可作为包装后实重和体积重的上界约束。
6. 因此，本轮**不新增任何数值 CAL 规则**。原有保护规律、展示态纠错规律和小件包装 candidate 继续保留。

## 计算定义

当前业务费率：

- 义乌：100 RMB/kg
- 深圳：80 RMB/kg

本轮定义：

`费率等价计费重量 = 实际纯头程 / 货代费率`

注意：这里刻意称为“费率等价计费重量”，而不是直接声明为真实物理计费重。原因是当前校准记录没有保存货代是否存在最低计费、进位或账单取整规则。

如果后续确认真实货代就是线性 `计费重量 × 单价`、不存在额外进位/最低计费，则：

- 包装后实际重量 ≤ 该重量
- 运输体积 / 8000 ≤ 该重量
- 即运输总体积 ≤ 该重量 × 8000 cm³
- 两者至少有一项接近计费重量

但即便如此，仍然不能只凭一笔运费确定唯一 L×W×H。

## 对已有规律的新验证

### 1. 展示/支撑态 ≠ 运输态：继续成立，但不能形成固定压缩率

7 条用户明确支持的异常样本：

- CAL-0019: baseline/actual=25/6 RMB，实际/基线=0.240
- CAL-0026: baseline/actual=46.88/12 RMB，实际/基线=0.256
- CAL-0047: baseline/actual=18.9/7 RMB，实际/基线=0.370
- CAL-0050: baseline/actual=52.81/23.5 RMB，实际/基线=0.445
- CAL-0071: baseline/actual=68.75/44.2 RMB，实际/基线=0.643
- CAL-0074: baseline/actual=7.5/2.85 RMB，实际/基线=0.380
- CAL-0077: baseline/actual=216.77/18.05 RMB，实际/基线=0.083

这 7 条“实际/基线”比例从 **0.083 到 0.643**，中位数约 **0.370**，离散非常大。

因此这批真实数据反而进一步证明：

- “可折叠/可压缩、展示态不等于运输态”是可靠物理原则；
- **不能**从这 7 条生成统一 0.4、0.6、0.8 等固定压缩倍率；
- 后续如果要形成数值修正，必须先获得能够判断实重/体积重主导的额外证据。

### 2. 小件盒装/防护包装低估：仍是 candidate，不升级数值规则

4 条现有 candidate：

- CAL-0021: baseline/actual=2.5/7 RMB，实际/基线=2.800
- CAL-0029: baseline/actual=1.5/5 RMB，实际/基线=3.333
- CAL-0031: baseline/actual=5/8 RMB，实际/基线=1.600
- CAL-0033: baseline/actual=7/17 RMB，实际/基线=2.429

实际/基线比例约 **1.60–3.33**，方向稳定为低估，但离散仍明显。

当前无法判断额外费用究竟主要来自：

- 包装增加的实重；
- 包装增加的体积；
- 两者共同作用。

所以继续保持 `PATTERN_CANDIDATE`，不生成固定“加多少克 / 放大多少体积”的规则。

这是边界放宽，不是新增规则引擎。

## 后续何时才允许升级到更高证据

### 可判断实重主导 / 体积重主导

至少需要一项独立于 AI shipment 的可信证据，例如：

- 实际包装后重量；
- 商家明确裸重 + 有依据的包装重量范围；
- 明确实际包装尺寸；
- 货代称重/体积记录。

当前 v1.3 AI baseline 的 weight/dimensions 只能作为“被校准对象”，不能反过来当作证明自身正确的 truth。

### 可估计运输总体积

只有在有证据确认“体积重主导”后，才可以用：

`总体积 ≈ 计费重量 × 8000`

如果货代存在进位，则应输出区间而不是单点值。

### 可估计长宽高范围

除了体积重主导，还必须有独立的形状/尺寸约束，例如：

- 可信裸尺寸；
- 明确不可折轴；
- 可靠硬结构；
- 明确折叠/盘卷/压缩方式；
- 用户真实包装备注。

仍然禁止仅靠总体积拆出唯一长宽高。
